DOCUMENTAÇÃO DO CÓDIGO
Corpus de descrições biofísico-químicas de proteínas (UniProt)
Arquivos: codigo/coletar.py e codigo/json_para_csv.py
==========================================================================


1. VISÃO GERAL
--------------------------------------------------------------------------
Os dois programas fazem a coleta e a organização descritas no guia de
trabalho (passos 2 a 7 e 9).

  coletar.py ........ baixa os registros do UniProt, guarda as respostas
                      originais, extrai as descrições de pH e temperatura
                      e gera o corpus, a amostra, as ocorrências e as
                      contagens.
  json_para_csv.py .. converte os arquivos .jsonl em .csv e confere se o
                      conteúdo ficou igual.

Ficam fora destes programas: a conferência manual das 20 descrições
(conferencia.csv), o resumo do passo 8 (resumo.csv), os gráficos, o
relatorio.md e o README.md.


2. REQUISITOS
--------------------------------------------------------------------------
  - Python 3.8 ou superior.
  - Biblioteca requests:   pip install requests
    (a urllib3, também usada, é instalada junto com a requests)
  - json_para_csv.py usa apenas a biblioteca padrão do Python.
  - Acesso à internet só é necessário durante a coleta.


3. COMO EXECUTAR
--------------------------------------------------------------------------
Rode sempre a partir da raiz do projeto (a pasta que contém codigo/).

  Primeira entrega (amostra de 100 descrições):
      python codigo/coletar.py --amostra
      python codigo/json_para_csv.py

  Entrega final (corpus ampliado):
      python codigo/coletar.py
      python codigo/json_para_csv.py

  Conferência antes de entregar (refaz tudo a partir de originais/):
      python codigo/coletar.py
      python codigo/json_para_csv.py
  Com a coleta completa, o coletar.py não acessa a rede: só reextrai.

Opções do coletar.py:
  --amostra       Para a coleta assim que houver pelo menos 100 descrições
                  com as duas categorias. Sem essa opção, segue até a
                  última página.
  --saida PASTA   Pasta do projeto onde tudo é gravado (padrão: a atual).
                  Use outra pasta para começar uma coleta nova.
  --tamanho N     Registros por página, de 1 a 500 (padrão: 50). Só vale
                  na primeira execução de uma pasta; depois, o script
                  continua com o tamanho já usado.

Uso do json_para_csv.py:
      python codigo/json_para_csv.py                 (converte os três)
      python codigo/json_para_csv.py corpus.jsonl    (converte só esse)
  Sem argumentos, converte corpus.jsonl, corpus_amostra.jsonl e
  ocorrencias.jsonl. Cada X.jsonl gera um X.csv na mesma pasta.


4. ARQUIVOS GERADOS
--------------------------------------------------------------------------
  originais/
      coleta.json ............ registro da coleta (ver 5.2)
      pagina_0001.json ....... respostas da API, gravadas sem alteração
      pagina_0002.json
      ...
  corpus.jsonl / .csv ........ todas as descrições extraídas até agora
  corpus_amostra.jsonl / .csv  as 100 primeiras descrições (fixa)
  ocorrencias.jsonl / .csv ... casos separados por problema ou dúvida
  extracao.json .............. contagens da última extração (ver 9)

Diferença entre corpus e amostra:
  - corpus_amostra é criada uma única vez e depois preservada, como
    referência da primeira entrega.
  - corpus é regravado a cada execução e cresce até conter todas as
    descrições elegíveis da consulta.


5. coletar.py EM DETALHE
--------------------------------------------------------------------------

5.1 Constantes (início do arquivo)

  CONSULTA            "reviewed:true AND cc_bpcp:*" (passo 2 do guia).
  BASE                Endereço de busca da API do UniProt.
  BPCP                Tipo do comentário que contém os campos de interesse
                      ("BIOPHYSICOCHEMICAL PROPERTIES").
  CAMPOS              Nomes dos campos na fonte e a categoria que recebem:
                      phDependence          -> ph_dependence
                      temperatureDependence -> temperature_dependence
  CHAVES_CONHECIDAS   Chaves esperadas no comentário BPCP. Uma chave fora
                      desta lista gera uma ocorrência para conferência.
  N_AMOSTRA           Tamanho da amostra (100).

5.2 Coleta - função coletar()

  1. Monta a URL inicial com a consulta, formato JSON, o tamanho de página
     e ordenação por identificador (sort=accession asc).
  2. Se originais/coleta.json já existe, retoma a partir da página
     registrada em "proxima". Se não existe, começa do zero.
  3. Para cada página:
       - Faz a requisição. Erros temporários (429, 500, 502, 503, 504) são
         repetidos até 6 vezes, com espera crescente.
       - Lê a versão do UniProt no cabeçalho X-UniProt-Release. Se for
         diferente da versão registrada, interrompe e pede outra pasta,
         para não misturar versões.
       - Confere se a resposta tem a lista "results". Se não tiver,
         interrompe, para que um formato inesperado não seja tratado como
         ausência de dados.
       - Grava a resposta exatamente como recebida em pagina_NNNN.json.
       - Atualiza coleta.json, gravando primeiro um arquivo temporário e
         depois substituindo o original, para não corromper o registro se
         o programa for interrompido no meio.
       - A próxima página vem do cabeçalho Link (paginação por cursor).
  4. Se a conexão falhar de vez, mostra um aviso, mantém o que já foi
     salvo e segue para a extração. A coleta fica marcada como "parcial".
     Uma falha nunca é registrada como página vazia.

  Campos de coleta.json:
    consulta               consulta usada
    url_inicial            endereço da primeira página
    inicio                 data e hora (UTC) do início da coleta
    versao_uniprot         versão do banco (ex.: 2026_04)
    data_versao            data de lançamento dessa versão
    total_registros_busca  total de REGISTROS informado pela busca
                           (não é o total de descrições)
    paginas                lista com arquivo, url, número de registros e
                           data de cada página baixada
    proxima                endereço da próxima página, ou null quando a
                           coleta terminou

5.3 Extração - função extrair()

  Lê as páginas listadas em coleta.json, na ordem em que foram baixadas.
  Para cada registro:
    1. Pega o identificador (primaryAccession) e a sequência
       (sequence.value).
    2. Procura os comentários do tipo BIOPHYSICOCHEMICAL PROPERTIES e
       guarda a posição de cada um na lista comments.
    3. Dentro deles, percorre phDependence.texts e
       temperatureDependence.texts. CADA ELEMENTO DESSAS LISTAS VIRA UMA
       LINHA DO CORPUS (passo 4 do guia):
         - uma proteína com um texto de pH e um de temperatura gera
           2 linhas;
         - um texto com várias frases continua sendo 1 linha;
         - dois elementos no mesmo campo geram 2 linhas.
    4. Registros sem nenhum texto nesses dois campos (por exemplo, só com
       parâmetros cinéticos) não geram linhas e são contados em
       "registros_sem_ph_nem_temperatura". Não são ocorrências: são
       exclusões previstas pelas regras.
    5. Cada candidata a linha passa pelas verificações da seção 8. Se
       falhar, vai para as ocorrências em vez do corpus.

  No fim, as linhas são ordenadas por description_id.

  Normalização (text_normalized): " ".join(texto.split()). Remove espaços
  nas pontas e troca qualquer sequência de espaços, tabulações ou quebras
  de linha por um único espaço. Nada mais é alterado: palavras,
  maiúsculas, pontuação, números, unidades e negações ficam iguais.
  text_original guarda o texto intacto.

  Evidências: vêm de texts[j].evidences, ou seja, só as evidências daquele
  texto. As publicações do registro não são associadas automaticamente a
  todos os textos. Sem evidências, a coluna recebe uma lista vazia [].

5.4 Regra da amostra - funções pronta() e amostra()

  pronta(): verdadeira quando há pelo menos 100 descrições e as duas
  categorias aparecem. No modo --amostra, a coleta para assim que isso
  acontece.

  amostra(): pega as 100 primeiras descrições por description_id. Se uma
  categoria não aparecer entre elas, troca a última linha pela primeira
  descrição dessa categoria, na mesma ordem. Se a categoria não existir
  nos dados, nada é inventado. Com menos de 100 descrições disponíveis,
  a amostra traz todas.

  A amostra só é gravada se o arquivo ainda não existir e se as
  descrições forem suficientes (ou a coleta tiver terminado). Assim, uma
  coleta interrompida cedo não grava uma amostra incompleta.

5.5 Fluxo principal - função main()

  1. Lê as opções da linha de comando.
  2. Coleta (ou retoma, ou pula, se a coleta já terminou).
  3. Extrai as descrições de todas as páginas salvas.
  4. Grava corpus.jsonl e ocorrencias.jsonl.
  5. Grava corpus_amostra.jsonl, se ainda não existir.
  6. Grava extracao.json e mostra as contagens na tela.


6. json_para_csv.py EM DETALHE
--------------------------------------------------------------------------
  1. Lê o .jsonl linha a linha.
  2. As colunas do CSV são as chaves dos registros, na ordem em que
     aparecem.
  3. Listas e objetos (como evidences) são gravados como texto JSON dentro
     da célula, sem perder itens. Valores nulos viram célula vazia.
  4. Depois de gravar, relê o CSV e compara linha por linha com o JSONL.
     Se houver qualquer diferença, para com erro. A mensagem
     "conteúdo conferido" confirma que os dois formatos têm as mesmas
     linhas e o mesmo conteúdo (passo 7 do guia).
  5. Arquivo .jsonl vazio gera um .csv só com o cabeçalho. Isso deixa
     registrado, por exemplo, que não houve ocorrências.

  O CSV é gravado em UTF-8, com aspas onde necessário, o que preserva
  vírgulas, aspas e quebras de linha dentro dos textos.


7. COLUNAS DO CORPUS
--------------------------------------------------------------------------
  description_id   accession + ":" + source_path. Único nesta coleta;
                   não é um identificador permanente entre versões.
  accession        primaryAccession (ex.: A0A023I7E1).
  organism         organism.scientificName (null se ausente).
  sequence         sequence.value, sem alteração.
  entry_version    entryAudit.entryVersion: versão do registro, diferente
                   da versão geral do banco (null se ausente).
  property_type    ph_dependence ou temperature_dependence, conforme o
                   campo de origem.
  text_original    texts[j].value, exatamente como na fonte.
  text_normalized  cópia com espaços padronizados (ver 5.3).
  evidences        texts[j].evidences; [] se ausente.
  source_file      página de onde a linha veio (ex.:
                   originais/pagina_0001.json).
  source_path      posição do texto dentro do registro, com índices (ex.:
                   comments[3].phDependence.texts[0]).

  Para achar uma linha na fonte: abra source_file, localize o registro
  pelo accession e siga source_path.


8. OCORRÊNCIAS: MOTIVOS E DECISÕES
--------------------------------------------------------------------------
Campos: source_file, indice_registro (posição do registro na lista
results da página), accession, source_path, motivo, decisao.

  motivo                                   decisao
  ---------------------------------------  ------------------------------
  sem identificador                        separada do corpus
  sem sequência                            separada do corpus
  texto não interpretável (não é texto     separada do corpus
    ou está vazio)
  descrição duplicada (mesmo elemento do   separada do corpus
    mesmo registro processado duas vezes)
  sem comentário BPCP, embora a busca o    nada extraído; conferir
    exija                                    estrutura
  campo desconhecido: [...]                descrições mantidas; conferir

As duas últimas servem para detectar mudanças na estrutura dos arquivos,
para que um campo renomeado não pareça ausência de informação biológica.

Textos iguais em proteínas diferentes NÃO são ocorrências: permanecem no
corpus, como pede o guia.

Na primeira coleta real, o arquivo ficou vazio, o que indica que os
registros vieram completos e com a estrutura esperada.


9. CONTAGENS EM extracao.json
--------------------------------------------------------------------------
  consulta, versao_uniprot, data_versao   identificação da coleta
  situacao                  "completa" (não há próxima página) ou
                            "parcial"
  paginas                   páginas baixadas
  registros_na_busca        total de registros informado pela API
  registros_processados     registros lidos das páginas salvas
  registros_sem_ph_nem_temperatura  registros excluídos por não terem
                            texto nos dois campos
  descricoes                linhas do corpus
  proteinas                 accessions distintos no corpus
  por_categoria             descrições de pH e de temperatura
  total_ocorrencias         quantidade de ocorrências (0 se nenhuma)
  ocorrencias               contagem por motivo, ou "nenhuma ocorrência
                            encontrada"

Atenção: registros_na_busca conta registros, descricoes conta linhas.
São números diferentes e não devem ser confundidos (passo 9 do guia).


10. SITUAÇÕES ESPECIAIS
--------------------------------------------------------------------------
  Falha de conexão
      O script avisa, mantém tudo que já baixou e marca a coleta como
      parcial. Rode de novo o mesmo comando para continuar da última
      página concluída.

  Mudança de versão do UniProt no meio da coleta
      O script para. Comece uma coleta nova em outra pasta:
          python codigo/coletar.py --saida coleta_nova

  Resposta em formato inesperado
      O script para e mostra o endereço da página. Abra a resposta no
      navegador e confira antes de continuar.

  Começar uma coleta do zero
      Use outra pasta com --saida. Não apague arquivos de originais/ de
      uma coleta em andamento.

  Recriar a amostra
      Apague corpus_amostra.jsonl e rode o coletar.py de novo. Se as
      páginas necessárias já estão em originais/, nada é baixado.


11. REPRODUZIR E CONFERIR
--------------------------------------------------------------------------
O guia pede que, antes da entrega, a organização seja refeita a partir
dos arquivos salvos. Com a coleta completa, basta rodar de novo os dois
scripts: o coletar.py não acessa a rede e o resultado deve ser idêntico.

Para comparar, calcule a assinatura do arquivo antes e depois:
    python -c "import hashlib;print(hashlib.sha256(open('corpus.jsonl','rb').read()).hexdigest())"
Os dois valores devem ser iguais.


12. LIMITAÇÕES E CUIDADOS
--------------------------------------------------------------------------
  - A amostra não é aleatória. Como segue a ordem dos identificadores, só
    reúne proteínas cujo accession começa com A0A0... e não representa o
    UniProt como um todo.
  - A ordenação é alfabética. Em um registro com 10 ou mais textos no
    mesmo campo, texts[10] viria antes de texts[2]. É raro e não afeta o
    conteúdo.
  - A sequência guardada é a do registro. O texto pode se referir a uma
    variante, um domínio ou outra forma da proteína.
  - Nem toda evidência é experimental. O campo evidenceCode usa códigos
    ECO; por exemplo, ECO:0000269 indica evidência experimental e
    ECO:0000303, uma declaração de autor sem suporte rastreável.
  - Os arquivos de originais/ guardam os registros completos (sequência,
    referências, anotações etc.) e podem ocupar bastante espaço na coleta
    completa.
  - O Excel corta células com mais de 32.767 caracteres. Uma sequência
    muito longa pode parecer truncada na planilha, mas o CSV e o JSONL
    continuam íntegros.
  - No CSV, um valor nulo e um texto vazio aparecem da mesma forma (célula
    vazia). Para distinguir, use o JSONL.


13. COMO ADAPTAR
--------------------------------------------------------------------------
  Mudar a consulta ........ edite CONSULTA e use outra pasta (--saida).
  Mudar o tamanho da
    amostra ............... edite N_AMOSTRA.
  Chave nova no comentário
    BPCP .................. se ela for legítima e aparecer em quase todos
                            os registros como "campo desconhecido",
                            adicione-a a CHAVES_CONHECIDAS.
  Incluir outro campo ..... acrescente o par nome_na_fonte: categoria em
                            CAMPOS (fora do escopo atual do guia).


14. TESTES REALIZADOS
--------------------------------------------------------------------------
  Com uma API simulada:
    - paginação por cursor e leitura dos cabeçalhos de versão;
    - falha 503 no meio da coleta e retomada da página seguinte;
    - reextração sem rede gerando arquivos idênticos byte a byte;
    - ocorrências: sem sequência, sem comentário BPCP, texto não
      interpretável e campo desconhecido;
    - normalização de espaços e quebras de linha;
    - amostra com o limite padrão de 100, inclusive a troca da última
      linha quando falta uma categoria;
    - conversão para CSV com conferência do conteúdo e arquivo vazio.

  Com dados reais:
    - registro A0A023I7E1: duas linhas, com source_path
      comments[3].phDependence.texts[0] e
      comments[3].temperatureDependence.texts[0];
    - primeira coleta (páginas 1 a 3): amostra com 100 descrições únicas
      de 63 proteínas, 59 de pH e 41 de temperatura, em ordem, sem
      ocorrências.
